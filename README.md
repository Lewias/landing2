# Feel Agency — landing

Одностраничный лендинг, свёрстанный по макету `design/reference-full.jpg`.

## Стек

| Из задания        | Что используется                | Почему                                                        |
| ----------------- | ------------------------------- | ------------------------------------------------------------- |
| Vue 3 + Vite      | `vue`, `vite`                   | —                                                              |
| TypeScript        | `typescript`, `vue-tsc`         | строгий режим, сборка падает на ошибке типов                   |
| Tailwind CSS      | `tailwindcss` v4 + `@tailwindcss/vite` | тема через `@theme` в `src/style.css`, без `tailwind.config` |
| shadcn/ui         | **shadcn-vue** (`reka-ui` + `cva`) | shadcn/ui — React; во Vue это порт shadcn-vue на Reka UI    |
| Framer Motion     | **`motion-v`**                  | Framer Motion — React; `motion-v` это официальный Motion для Vue |
| Lucide React      | **`lucide-vue-next`**           | `lucide-react` — React; это тот же набор иконок для Vue        |

Без базы данных и без бэкенда: весь контент страницы лежит в `src/data/site.ts`
обычными типизированными объектами, компоненты читают только оттуда.

## Деплой на VDS

Проект собирается в статику — `npm run build` кладёт готовые файлы в `dist/`.
Node-процесса в рантайме нет, поэтому **pm2 здесь не нужен**: nginx отдаёт
папку напрямую.

### Первый раз

```bash
# 1. Node не ниже 20.19 (или 22.12) — Vite 7 на более старых не соберётся
node -v

# 2. Забрать код. Именно в /var/www, НЕ в /root и не в домашнюю папку:
#    у /root права 700, и nginx (работает от www-data) получит 403 на всё.
sudo mkdir -p /var/www && cd /var/www
sudo git clone <репозиторий> landing2 && cd landing2

# 3. Ключи Telegram. .env.local в git не попадает, поэтому создаётся руками
cp .env.example .env.local && nano .env.local

# 4. Собрать
npm ci
npm run build

# 5. Отдать nginx — см. ниже, вариант зависит от того, есть ли уже сертификат
```

### nginx: домен уже настроен и у него есть сертификат

Это самый частый случай: certbot уже создал блок с `listen 443 ssl`, а внутри
стоит `proxy_pass` на старое приложение. **Новый конфиг создавать не надо** —
второй блок с тем же доменом только конфликтует, а с чужим `server_name` он
ещё и перехватывает трафик как сервер по умолчанию.

Найти нужный файл:

```bash
grep -rln "твой-домен" /etc/nginx/sites-available/
```

Открыть его и в блоке `listen 443 ssl` заменить `location / { proxy_pass ...; }`
на три строки:

```nginx
root  /var/www/landing2/dist;
index index.html;
include /var/www/landing2/deploy/static-locations.conf;
```

Строки `ssl_certificate`, `listen` и `server_name` не трогать — они уже верные.
Проверить, что в `server_name` есть оба варианта: `домен.com www.домен.com`.

```bash
sudo nginx -t && sudo systemctl reload nginx
```

Старое приложение после этого можно убрать: `pm2 delete <имя>`.

### nginx: домена ещё нет

Сначала убедись, что имя свободно — перезапись чужого конфига уничтожит
строки сертификата, которые туда прописал certbot:

```bash
ls -la /etc/nginx/sites-available/
sudo cp deploy/nginx-new-site.conf.example /etc/nginx/sites-available/landing2
sudo nano /etc/nginx/sites-available/landing2   # ОБЯЗАТЕЛЬНО: server_name и root
sudo ln -sf /etc/nginx/sites-available/landing2 /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
```

Сертификат потом: `sudo certbot --nginx -d домен.com -d www.домен.com`.

### Каждое следующее обновление

```bash
cd /var/www/landing2 && bash deploy/deploy.sh
```

Через `bash ...`, а не `./deploy/deploy.sh`: файл приезжает из репозитория,
собранного на Windows, и бит запуска может не сохраниться. `bash` его не
требует. Если хочется запускать напрямую — один раз `chmod +x deploy/deploy.sh`.

Или руками, если привычнее:

```bash
cd /var/www/landing2 && git pull && npm ci && npm run build
```

`pm2 restart` больше не нужен — nginx читает файлы с диска, они меняются сразу.

### Чтобы сайт не падал

Держать запущенным нечего: `dist/` — это файлы на диске, отдельного процесса у
проекта нет. Единственное, что должно работать постоянно, — nginx.

```bash
sudo systemctl enable nginx     # подниматься после перезагрузки сервера
sudo systemctl status nginx     # должно быть: active (running), enabled
```

`enable` — это и есть ответ на «чтобы всегда был запущен». После ребута nginx
стартует сам и сразу отдаёт файлы: пересобирать ничего не надо.

Стандартный юнит nginx в Debian и Ubuntu не всегда содержит `Restart=`, то есть
после падения сервис останется лежать, пока кто-нибудь не заметит. Чтобы systemd
поднимал его сам:

```bash
sudo mkdir -p /etc/systemd/system/nginx.service.d
sudo cp deploy/nginx-restart.conf /etc/systemd/system/nginx.service.d/override.conf
sudo systemctl daemon-reload && sudo systemctl restart nginx
```

Проверить, что автозапуск реально включён:

```bash
systemctl is-enabled nginx      # enabled
systemctl show nginx -p Restart # Restart=on-failure
```

### Что ломается чаще всего

- **`.env.local` не создан на сервере.** Он в `.gitignore`, поэтому с GitHub не
  приезжает. Без него `VITE_TELEGRAM_*` пустые, форма молча уходит в почтовый
  клиент вместо Telegram, и никакой ошибки не видно. `deploy.sh` проверяет это
  и останавливается.
- **Ключи подставляются на сборке, а не в рантайме.** Поменял `.env.local` —
  обязательно пересобери, иначе в бандле останутся старые значения.
- **Старый Node.** Vite 7 требует `^20.19.0 || >=22.12.0`. На Node 18 сборка
  падает с невнятной ошибкой про синтаксис.
- **Проект лежит в `/root` или в домашней папке.** У `/root` права `700`, у
  многих домашних папок тоже. nginx работает от `www-data` и получит 403 на
  каждый файл, при том что `nginx -t` пройдёт успешно. Проверяется так:
  `sudo -u www-data stat /путь/к/dist`. Лечится переносом в `/var/www`.
- **`./deploy/deploy.sh` -> Permission denied.** Бит запуска потерялся при
  переносе с Windows. Запускай `bash deploy/deploy.sh` или разово сделай
  `chmod +x deploy/deploy.sh`.
- **Остался включённым дефолтный конфиг nginx.** `/etc/nginx/sites-enabled/default`
  может перехватывать домен раньше твоего блока. Удали его и перезагрузи nginx.
- **Два блока на один домен.** Если конфиг с сертификатом уже есть, а рядом
  положить второй — они конфликтуют, и запрос уходит не туда. Хуже того:
  скопированный и не отредактированный пример с `server_name example.com`
  становится сервером по умолчанию и ловит вообще весь трафик. В логе это
  видно так: `server: example.com` при `host: твой-домен`. Лечится удалением
  лишнего конфига и правкой существующего.
- **Копирование конфига поверх существующего.** Имя файла в
  `sites-available` часто совпадает с именем старого приложения. Копия затрёт
  блок с `ssl_certificate`, который писал certbot, и HTTPS отвалится. Всегда
  сначала `ls -la /etc/nginx/sites-available/`. Восстановить можно так:
  сертификаты остаются в `/etc/letsencrypt/live/`, поэтому достаточно создать
  http-блок заново и выполнить `certbot --nginx -d домен -d www.домен` — он
  подхватит существующий сертификат и допишет 443-й блок сам.
- **`nginx -t` проходит, а сайт не работает.** Тест проверяет только синтаксис.
  Ни существование папки из `root`, ни права на неё он не проверяет. Настоящую
  причину показывает `sudo tail -20 /var/log/nginx/error.log`.
- **Мало памяти.** `vue-tsc` при сборке ест около 1 ГБ. На VDS с 512 МБ без
  swap сборка падает по OOM — тогда собирай локально и заливай только `dist`:
  `rsync -avz --delete dist/ user@server:~/site/dist/`

### Проверить, что доехало

```bash
# что вообще отвечает сервер и куда смотрит nginx
curl -sI http://localhost/ | head -3
sudo tail -20 /var/log/nginx/error.log
curl -sI https://твой-домен/ | head -3
curl -s https://твой-домен/ | grep -o 'index-[a-zA-Z0-9_-]*\.js'   # хеш меняется после сборки
curl -sI https://твой-домен/review/lithegoat.mp4 | grep -i 'content-type\|content-length'
```

## Анимации

- Первый экран — появление сразу после загрузки, со ступенчатой задержкой.
- Всё ниже — `Reveal.vue`: `whileInView` с `once: true` и `amount: 0.2`,
  то есть анимация запускается только когда блок реально попал в кадр.
- Бегущая строка площадок — CSS-анимация, а не JS: не зависит от rAF и
  выключается медиазапросом `prefers-reduced-motion`.
- Аккордеон раскрывается по измеренной Reka UI высоте контента.

## Про артворк с телефонами

`public/phones.webp` (+ `.jpg` как fallback) — это кроп исходной картинки
`design/phones-source.jpg`. Фон исходника — чистый `#000`, ровно как фон
страницы, поэтому картинка ложится без видимых границ и не требует маски.

На десктопе (`lg`) артворк вынут из потока (`position: absolute`): в макете его
чёрные поля заходят на строку метрик, а высоту секции задаёт только колонка с
текстом. На узких экранах он возвращается в поток и встаёт под текстом.

## Медиа

**Кейс CAIRO!** (`public/result/cairo.webp`) — скриншот профиля Spotify,
обрезанный от боковой панели плеера и переведённый в webp (58 КБ вместо 1.1 МБ
PNG). Цифры в блоке слева считаны с оригинала в полном разрешении:

| | |
| - | - |
| Слушателей в месяц | 250 853 |
| HEATSEEKER | 33 867 132 |
| Топ-5 треков вместе | 72.3M |

Скриншот кликабельный — открывается в полном размере в новой вкладке, потому
что мелкий текст Spotify на странице всё равно не прочитать.

**Видео-отзывы** (`public/review/`) — три вертикальных ролика. Исходники были
13 МБ на троих (включая `.MOV`, который не во всех браузерах играет). Все
перекодированы в mp4 H.264 + AAC, CRF 28, `+faststart`, максимум 720px по
ширине — стало 3.7 МБ. Для каждого вытащен постер-кадр.

Ролики не грузятся, пока их не запустят: `preload="none"` плюс постер. При
запуске одного остальные ставятся на паузу. Нативные контролы появляются
только после нажатия play, до этого карточка показывает постер и кнопку.

Перекодировать заново, если добавятся новые:

```bash
ffmpeg -i input.mov -vf "scale='min(720,iw)':-2" -c:v libx264 -crf 28 -preset slow   -pix_fmt yuv420p -c:a aac -b:a 96k -movflags +faststart output.mp4
ffmpeg -ss 1 -i input.mov -frames:v 1 -vf "scale='min(720,iw)':-2" -q:v 4 output-poster.jpg
```

## Форма заявки

Форма живёт в модальном окне и открывается по кнопке — на странице её нет.
Три поля: Instagram username (с префиксом `@` внутри поля), email и
многострочное описание с плейсхолдером «Tell us about your release».

**Что открывает модалку** — все семь CTA на странице:

| Где | Кнопка |
| --- | ------ |
| Шапка | Let's talk |
| Первый экран | Get free content plan |
| Тарифы | Start with 40 / Get free plan / Talk to us |
| Финальный CTA | Get free content plan |
| Футер | Get a content plan |

Состояние открытия — один общий `ref` в `src/lib/apply-modal.ts`, поэтому
любая кнопка в любом месте страницы поднимает одну и ту же форму без проброса
пропсов и шины событий. Сама модалка (`ApplyDialog.vue`) собрана на
`Dialog` из Reka UI, поэтому бесплатно получает ловушку фокуса, закрытие по
Escape и по клику на подложку, блокировку прокрутки и корректные ARIA-роли.

Фокус при открытии ставится на первое поле, но только при `pointer: fine` —
на телефоне это выбрасывало бы клавиатуру поверх формы. После успешной
отправки форма перемонтируется при закрытии, чтобы в следующий раз открылась
чистой; недописанная заявка при случайном закрытии сохраняется.

**Куда уходит заявка.** Форма выбирает первый настроенный способ доставки:

1. **Telegram** — если заданы `VITE_TELEGRAM_BOT_TOKEN` и `VITE_TELEGRAM_CHAT_ID`.
2. **`endpoint`** в `src/data/apply.ts` — `POST` с JSON на любой свой URL.
3. Иначе открывается почтовый клиент с уже заполненным письмом.

### Telegram

Запрос уходит **из браузера посетителя** напрямую в Bot API, минуя сервер
сайта — поэтому не важно, откуда и куда ходит сам VDS.

Настройка:

```bash
cp .env.example .env.local
```

1. `@BotFather` -> `/newbot` -> скопировать токен.
2. Добавить бота в нужный чат, написать туда что-нибудь, открыть
   `https://api.telegram.org/bot<TOKEN>/getUpdates` и взять
   `result[0].message.chat.id`. Для личного чата подойдёт `@userinfobot`.
3. Вписать оба значения в `.env.local` и пересобрать — `VITE_*` подставляются
   на этапе сборки, а не в рантайме.

**Почему запрос именно form-encoded.** У `api.telegram.org` открытый CORS
(`Access-Control-Allow-Origin: *`), но на preflight-запрос `OPTIONS` он
отвечает **501 Not Implemented**, и браузер считает такой preflight
проваленным. Поэтому запрос обязан оставаться «простым»: тело собирается
через `URLSearchParams`, заголовок `Content-Type` руками не ставится, preflight
не отправляется вовсе. **Не переписывайте это на JSON-тело** — запрос
заблокируется, не выйдя из браузера.

> ### Токен виден всем
>
> Всё, что начинается с `VITE_`, подставляется в публичный JS-бандл. Токен
> бота сможет прочитать любой посетитель через DevTools и слать сообщения в
> ваш чат от имени бота.
>
> Чем это ограничить:
>
> - заведите отдельного бота только под эту форму;
> - не давайте ему прав администратора ни в одном чате или канале;
> - если начнётся спам — отзовите токен через `@BotFather` -> `/revoke`.
>
> Если токен должен остаться секретным — поднимите крошечный прокси на
> зарубежном хостинге (например, бесплатный Cloudflare Worker), который хранит
> токен у себя, и укажите его URL в `endpoint`. Тогда браузер шлёт заявку на
> прокси, а прокси — в Telegram.

**Защита от ботов.** В форме есть honeypot — поле за пределами экрана с
`tabindex="-1"` и `aria-hidden`, недоступное ни мышью, ни с клавиатуры, ни
скринридеру. Если оно заполнено, заявка молча отбрасывается без запроса в
Telegram.

**Если отправка не прошла** — сеть отвалилась, токен отозван, чат не найден —
показывается ошибка и ссылка «Send it by email instead» с уже заполненным
письмом, чтобы заявка не потерялась.

**Валидация** — на клиенте, до отправки. Пустые поля, email по формату,
описание не короче 10 символов. Ошибка показывается только после первой
попытки отправки или после ухода из поля — не дёргает во время набора. При
отправке фокус уезжает на первое поле с ошибкой, у полей проставляются
`aria-invalid` и `aria-describedby`, у сообщений — `role="alert"`.

**Мобильные.** Поля 54px высотой, размер текста ровно 16px — iOS Safari не
зумит страницу при фокусе. Модалка прижата к верху экрана и прокручивается,
если не помещается по высоте.

## Разрешения

Вся вёрстка описана в `rem` относительно макета 1280x853, а корневой размер
шрифта задан одной строкой в `src/style.css`:

```css
html { font-size: clamp(1rem, min(1.125vw, 1.85vh), 1.8rem); }
```

Три слагаемых:

- `1.125vw` держит контейнер примерно на 90% ширины окна, чтобы на 2K и 4K
  дизайн не оставался узкой полосой посередине экрана;
- `1.85vh` ограничивает масштаб по высоте, чтобы первый экран вместе со строкой
  метрик по-прежнему помещался целиком на 16:9;
- нижняя граница `1rem` оставляет всё до ~1400px пиксель-в-пиксель как в макете,
  а запись в `rem` вместо `px` сохраняет увеличенный системный шрифт
  пользователя.

Что получается на практике:

| Экран       | Масштаб | Контейнер | Поля по бокам | Первый экран |
| ----------- | ------- | --------- | ------------- | ------------ |
| 1280 x 853  | 1.00x   | 1280      | 0             | помещается   |
| 1440 x 900  | 1.01x   | 1296      | 72            | помещается   |
| 1920 x 1080 | 1.25x   | 1598      | 161           | помещается   |
| 2048 x 1152 | 1.33x   | 1705      | 172           | помещается   |
| 2560 x 1440 | 1.66x   | 2131      | 214           | помещается   |
| 3440 x 1440 | 1.66x   | 2131      | 654           | помещается   |

На 1366x768 первый экран целиком не влезает — экран ниже макета даже при
минимальном масштабе, строка метрик уходит под сгиб.

Раскладка по брейкпоинтам:

| Ширина    | Шапка                                  | Герой                       | Сетки секций |
| --------- | -------------------------------------- | --------------------------- | ------------ |
| < 640     | логотип + бургер, контакты в меню      | одна колонка, артворк снизу | 1 в ряд      |
| 640–767   | + иконка Instagram                     | одна колонка                | 2 в ряд      |
| 768–1023  | + почта и «Let's talk»                 | одна колонка                | 2 в ряд      |
| 1024–1279 | + навигация по секциям, бургер скрыт   | текст слева, артворк справа | 2–3 в ряд    |
| ≥ 1280    | как в макете                           | как в макете                | 3–4 в ряд    |

Горизонтальной прокрутки нет ни на одной ширине: проверено автоматическим
обходом всех элементов на 320 / 360 / 375 / 414 / 640 / 768 / 1024 / 1280 /
1440 / 1920 / 2560 px.

## Соответствие макету

`npm run design:diff` снимает страницу в 1280×853 и сравнивает положение
ключевых элементов с макетом по пикселям. Текущее расхождение — не больше 1–3 px
по вертикали и горизонтали.

Осознанные отличия:

- **Шрифт.** В макете растр, исходной гарнитуры нет. Взят Archivo (переменный,
  есть ось `wdth`); `font-stretch: 89%` подогнан так, чтобы ширины строк
  заголовка совпали с макетом. Числовой ряд «100+VIDEOS» у Archivo шире
  оригинала примерно на 30 px — сужать только цифры не стал, это ломает
  однородность набора.
- **Поля контейнера.** В макете справа поле ~35 px, слева 45 px. Сделано
  симметрично по 45 px.
- **Подпись на CTA** в макете сдвинута от центра влево; здесь отцентрована.
- **Навигация в шапке** макетом не предусмотрена — длинной странице она
  нужна, поэтому добавлена в пустоту между логотипом и контактами. Позиции
  самого логотипа и блока контактов при этом не изменились.
- **Тексты, цифры, отзывы и цены** ниже первого экрана — рыба под вёрстку.

## Доступность

- Заголовок собирается из строк, у `h1` есть `aria-label` с цельной фразой,
  декоративные строки скрыты от скринридера.
- У артворка осмысленный `alt` с перечислением сцен и просмотров.
- `prefers-reduced-motion` читается синхронно на первом рендере — при
  включённой настройке анимации не проигрываются вовсе.
- Видимый фокус на всех интерактивных элементах.
